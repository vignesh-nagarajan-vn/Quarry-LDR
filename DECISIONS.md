# DECISIONS.md

Every deviation from the build spec and every delegated design decision, with a one line rationale. Measured numbers replace assumptions as they land.

## Development environment corrections (desktop PC, measured 2026-08-03)

The project was built and its pre-deployment tests were run on the desktop PC described here; the RTX 5060 Mobile laptop the build spec targets is a separate machine, validated in the deployment environment section below.

- **The development desktop's GPU is an RTX 4060 (Ada, compute capability 8.9, 8188 MiB, driver 572.16), not the RTX 5060 Mobile of the build spec.** `nvidia-smi` measured. `verify_gpu.py` therefore checks capability >= (8, 0) plus a real on-device matmul instead of hard-requiring `sm_120`; the cu128 wheel pin stays, so Blackwell cards also work. The 8 GB VRAM budget logic is unchanged.
- **Host is native Windows 11; WSL is not installed.** Runtime targets Windows natively (torch cu128 Windows wheels, llama.cpp Windows CUDA binary); code stays cross-platform via pathlib and platform detection; CI runs Ubuntu so the Linux path stays honest.
- **Docker is not installed, not merely stopped.** SearXNG ships fully configured; `quarry searxng up` detects missing Docker and prints exact remediation. Nothing else depends on Docker.
- **Tooling installed during M0:** uv 0.12.1 (astral.sh installer), GNU make 4.4.1 (winget, ezwinports), Python 3.12.13 (uv-managed). System Python was 3.9.

## Deployment environment (RTX 5060 Mobile laptop, measured 2026-08-04)

- **GPU: RTX 5060 Laptop GPU (Blackwell, sm_120), 8151 MiB, WDDM, driver 592.27 (CUDA 13.1).** torch 2.11.0+cu128 runs a real matmul on device; all gpu-marked tests pass.
- **The llama.cpp cuda-12.4 release asset (b10252) serves on sm_120 via one-time driver PTX JIT:** the first inference paid about 25 s of JIT (driver-cached persistently); post-warm-up, 645 tok/s prompt and 90.5 tok/s generation at the 70 W power cap, 93 percent utilization, 56 C. A cuda-13.3 asset exists; the 12.4 preference stands because it runs on every driver from the 12.8 generation up.
- **Sustained versus burst throughput: no thermal degradation observed.** Single triage verdict 1.71 s cold (bench); sustained triage held 1.0 to 1.9 s per verdict across 35-minute blocks with stable cadence first sub-question to last. Embedder benched 95.7 texts/s; live 542-chunk embed in 35 s including model load.
- **Runtime footprint self-correction varies with load order and stays within budget:** embedder measured 2076 to 2186 MB, reranker 978 to 2128 MB depending on what else was resident at load; the arbiter corrects per load, and the WDDM implausibility guard fired for the llama-server child on every live run, keeping the declared 3600 MB. Peak declared residency 6654 MB of the 6656 MB budget.
- **Known guard limitation, observed 2026-08-05:** WDDM once reported the synth llama-server load as a 2750 MB whole-card delta, which is 43 percent of the declared 6400 MB and therefore above the 25 percent implausibility floor, so the arbiter accepted a partially blind measurement. Harmless under the stage-batched design (the synth stage runs alone and every model is evicted before the next stage), but a co-residency scheme relying on corrected synth footprints would need a stricter guard for child-process loads.
- **This Windows build (26200.8875) corrupts AF_UNIX socket creation after sleep:** Docker Desktop (4.85.0 per-user, WSL 2.7.11) crashes at startup on corrupt, undeletable socket reparse points until the machine reboots; renaming the parent directory sidesteps stale files but only a reboot restores healthy binds. Disabling the Docker AI feature (EnableDockerAI in settings-store.json) reduces exposure. Keep the laptop awake during long runs.
- **uv 0.12.1 cannot install a managed Python on this machine** ("Missing expected target directory for Python minor version link", reproducible from clean state); the venv runs on system CPython 3.12.10. Smart App Control (enforce mode) one-time-blocked scipy's _zeros.pyd until its cloud reputation check cleared.

## Tooling and repo

- **ruff for both lint and format** (black-compatible defaults): one tool, one config, no second formatter dependency.
- **mypy for type checking** with `disallow_untyped_defs`: strict enough to catch real bugs without fighting untyped third-party libs.
- **pytest-socket** blocks all non-loopback sockets in the default selection: "no network in unit tests" is enforced, not hoped.
- **detect-secrets** for secret scanning: pip-installable, baseline committed, runs in pre-commit as a local hook so hooks need no network.
- **Local pre-commit hooks** (`language: system`) running `uv run ...`: hook versions are exactly the project's pinned versions.
- **Coverage excludes `raise NotImplementedError` lines**: standard exclusion that keeps the 80 percent gate honest through the interfaces-first build (stubs vanish as milestones land).
- **`bootstrap.ps1` added alongside `bootstrap.sh`**: the dev machine is native Windows; spec listed only the sh script.
- **`quarry searxng up|down|status` CLI subcommands** instead of an extra script: the spec's script list stays as specified, and the Docker preflight lives with the rest of the CLI UX.
- **Preflight's Docker check is a skip, not a blocking failure, when `search.searxng_url` is non-local (issue #5):** Docker only backs the bundled local SearXNG container, so a run pointed at an already-running instance elsewhere must not be refused for a missing docker binary; the default localhost URL still requires Docker. Research and resume gate on preflight, so the old unconditional failure made bring-your-own-SearXNG runs impossible despite the client supporting them.
- **T20 (flake8-print) ruff rule** enforces "no print outside the CLI layer" mechanically.
- **ASYNC230/240 ignored in ruff**: small local file reads/writes in async functions are deliberate; heavy IO (LanceDB, model loads) already routes through `asyncio.to_thread`, so the rule has nothing left to catch and only adds noise.
- **Audit exempts `.env` from the working-tree secret scan and redacts matched secrets (M10)**: a configured machine always holds the real key in `.env`, which made `make audit` unpassable exactly where reports are produced; safety holds because the separate `.env`-is-gitignored check still fails the audit on its own, and matched secret content is now reported by location only, never echoed (the previous behavior printed the live key to the console).
- **`HF_HUB_OFFLINE=1` set in `tests/conftest.py` (M10)**: with a warm cache, huggingface_hub still makes a per-file etag check over the network at model load, which pytest-socket rightly blocks; offline mode makes gpu-marked tests deterministic on any machine whose cache already holds the models (fetched outside pytest, e.g. by `scripts/bench_vram.py`).

## Pipeline parameters (from spec unless noted; tuned values get measured justification)

- Chunking 512 target / 64 overlap tokens; fragments under 48 tokens merge backward.
- Token counting is pluggable (`TokenCounter` protocol); both tests and the runtime pipeline currently use the ~4 chars/token heuristic. An HF-tokenizer counter would change only chunk granularity, not correctness, and would drag tokenizer downloads into the chunk stage; revisit if measured chunk sizes drift badly from 512 tokens.
- **Resume is replay, not special-case code**: every stage checkpoint stores the payload the next stage needs; re-driving a run returns persisted payloads for completed stages instantly (identical timestamps prove no recomputation) and executes only unfinished stages. Embeddings persist as npz per iteration since LanceDB only holds post-dedup rows.
- Dedup: 64-bit SimHash over 5-word shingles, Hamming <= 3, OR embedding cosine >= 0.92. Thresholds validated against the fixture near-duplicate set in M5.
- Fetch politeness: 1 request/second/domain token bucket, 8 global concurrent fetches, 20s timeout, 5 MB response cap, identifying user agent.
- **Local request timeouts are config keys, synth at 300s (measured, 2026-08-05):** the first full-length local run died an hour in with an httpx ReadTimeout when a full-corpus section outran the hardcoded 120s client ceiling on the thermally throttled 5060 laptop (sustained load runs well below the 35.3 tok/s burst bench). triage.request_timeout_s stays 120; synth.request_timeout_s ships at 300, sized for a 6000-heuristic-token prefill plus 2048 output tokens at deep-throttle speeds. The run resumed past the failure with every completed stage replayed from checkpoints, which is the recovery path Troubleshooting documents.
- Embedder default `BAAI/bge-m3` (dense, dim 1024); `Qwen/Qwen3-Embedding-0.6B` stays a config swap.
- Triage model `Qwen3-4B-Instruct-2507` Q4_K_M GGUF via llama-server, 8K context to keep KV cache small. Sourced from `unsloth/Qwen3-4B-Instruct-2507-GGUF`: Qwen publishes no official GGUF for the 2507 instruct variant (verified against the HF API, 2026-08-03); unsloth's conversion carries the expected filename and chat template.
- SearXNG on host port 8888 and llama-server on 8555: both defaults dodge the crowded 8080.
- Declared VRAM footprints are measured values since M10 (embedder 2186 MB, reranker 2128 MB, triage 3600 MB declared-only; see the M10 entry below); the arbiter still corrects declared values against `torch.cuda.mem_get_info` at every load.
- **SimHash Hamming <= 3 is nearly toothless standalone (measured, M5).** On the fixture corpus at ~100-200 words/chunk, scattered synonym swaps push near-duplicate chunk pairs to Hamming 0-14, so the shipped default of 3 catches under half of them SimHash-only, while the closest genuinely-unrelated pair sits at 13. The corpus regression test therefore runs SimHash-only at Hamming 10 (>=80 percent catch rate, zero false positives); the shipped default stays 3 because production dedup pairs SimHash with embedding cosine >= 0.92, where SimHash only needs to be a high-precision complement.
- **lancedb `list_tables()` over deprecated `table_names()`** (lancedb 0.36); merge_insert on chunk_id gives idempotent adds natively.
- **Windows WDDM hides child-process VRAM from mem_get_info (measured, M6).** llama-server's ~3.5 GB allocation measured as 0 MB from the parent process, which would have "corrected" the triage footprint to zero and broken all budget math. The arbiter now treats any measurement under 25 percent of the declared footprint as implausible and keeps the declared value (logged as footprint_measurement_implausible). Live lifecycle numbers on the desktop RTX 4060 (development PC): llama-server (Qwen3-4B-Instruct-2507 Q4_K_M, 8K context, full offload) healthy in 4.8 s, one structured triage verdict in 0.94 s, clean terminate under the arbiter.
- **llama.cpp release assets need a cudart-aware matcher.** The Windows CUDA runtime ships as a separate cudart-*.zip whose name also matches naive bin-win-cuda-x64 filters; download_models.py picks the llama-* build first and prefers CUDA 12.x (driver 572.16 supports 12.8, not 13.x). The server must be spawned with absolute -m paths because cwd is set to the binary directory for DLL resolution.
- **Synthesis corpus budget enforced at report.corpus_budget_tokens (M10, measured):** the first live smoke run shipped all 463 triaged chunks (about 300K tokens) into synthesis because nothing between triage and the corpus builder enforced the design's ~60K payload; the 1h cache write alone cost about $3.28 and the run recorded $3.37 against a $0.50 cap (the ledger cap is checked from usage blocks after each call returns, so it bounds loops, not a single oversized call). Evidence is now trimmed before corpus build, round-robin across sub-questions in descending rerank order, so coverage degrades evenly instead of dropping whole sub-questions.
- **Corpus budget calibrated to 45000 heuristic tokens and plan max_tokens raised to 8192 (M10, measured):** the second live run measured the heuristic-to-API tokenizer ratio at 1.32x (60000 heuristic tokens became a 79456-token cache write), so the default budget is 45000 heuristic tokens to land the design's ~60K API-token corpus; the ratio is corpus-shaped and worth re-measuring if chunking changes. The same run also truncated its first plan call at exactly max_tokens=4096 (claude-opus-5 thinks inside the output budget by default) and paid a $0.10 retry; plan headroom is now 8192. Smoke additionally caps report.max_sections at 6, mirroring its single-iteration depth override: the rehearsal exercises cache write, reads, and citations without paying for full report breadth.
- **Resume rebuilds citation numbering from the budget-selected subset, not the full evidence set (bug fix, issue #3):** both synthesis paths number `select_evidence(evidence, report.corpus_budget_tokens)`, so the persisted draft's [n] markers are numbered against the trimmed selection. A run resumed after SYNTHESIZE completed finds an empty CitationIndex and must rebuild that numbering; rebuilding from the full evidence set interleaves never-cited chunks and shifts every number, so markers resolve to the wrong sources whenever the budget trimmed anything (invariant 4 breaks on resume). The orchestrator now rebuilds from the same `select_evidence(...)` subset; an integration test crashes in VERIFY under a trimming budget and asserts the resumed references match an uninterrupted run's exactly. Local-only path, no API cost impact.
- **Search concurrency bounded at search.max_concurrency, default 4, and the SearXNG per-engine timeout raised to 6 s (M10, measured):** unbounded search_many gathers fired 56 to 60 concurrent queries per run; after five runs in one morning the shared engines suspended the IP (startpage CAPTCHA with suspended_time=3600, another engine 429 at 180 s, duckduckgo connect timeouts), and searches returned zero URLs while the pipeline kept spending on plan calls. Fetch always had politeness machinery; search now gets a semaphore. The 6 s engine timeout stops throttled-but-alive engines from being scored as dead at SearXNG's 3 s default.
- **Measured report economics on the claude 5 models (M10, 2026-08-04):** smoke (1 iteration, 6 sections) $1.36; the first substantive run (3 iterations, 10 sections, 57815-token cached corpus) $2.8846: plan $0.13, three sonnet gap calls $0.12, synthesis $2.63 (one $0.66 cache-write call plus nine cached reads averaging $0.22). Corpus transport measured $0.84 cached versus $2.89 uncached across ten sections, validating the projected caching ratio almost exactly; the per-report total exceeds the pre-launch $1.00 to $1.50 projection because adaptive thinking roughly doubles output tokens per call. Gap max_tokens raised from 2000 to 4096 after a live truncation retry, the same failure class fixed earlier for plan and sections.
- **VRAM footprints measured on the deployment RTX 5060 Laptop GPU (M10, 2026-08-03):** embedder (bge-m3) 2186 MB and reranker (bge-reranker-v2-m3) 2128 MB as `mem_get_info` deltas under the arbiter, against the 1400/1300 placeholders; config defaults now carry the measured values. Triage stays declared 3600 MB: WDDM reported 0 MB for the llama-server child and the implausibility guard (CLAUDE.md invariant 8) correctly kept the declared value, logging `footprint_measurement_implausible`. Throughput on this machine: 95.7 texts/s embed, 111.3 pairs/s rerank, one triage verdict in 1.71 s. Peak observed usage across the embed, rerank, and triage swap sequence was 5553 MB against the 6656 MB budget, with one LRU eviction (embedder) when triage joined the reranker.
- **Reranker regression measured on the desktop RTX 4060 development PC (M5):** mean nDCG@6 on the 5-query hand-labeled set is 0.958 for bge-reranker-v2-m3 versus 0.938 for a lexical word-overlap baseline. The margin is small because synthetic fixture chunks share exact wording with their queries, which flatters the baseline; the gpu-marked test asserts model >= baseline so a broken reranker path still fails. torch 2.11.0+cu128 verified with an on-device matmul (scripts/verify_gpu.py PASS).

## v1 engine tiers (local-first rebuild, M11+)

- **The single-provider design is amended (M11): stages type against a `Provider` protocol** (`providers/base.py`) satisfied by both the Anthropic client and the new llama-server-backed `LocalProvider`, so `engine.mode` can route PLAN/GAP/SYNTHESIZE to either backend. The original "no alternative providers by design" stance predates the v1 goal of zero-API-spend runs; depth over breadth still holds in that both backends share one contract, one ledger, and one cache-prefix rule.
- **Local calls are ledgered at zero price under a `local/` model-id prefix (M11)**, with real token counts taken from llama-server's OpenAI-compatible usage block, so invariant 2 (usage blocks, never estimates) spans both backends. Triage stays unmetered on purpose: hundreds of per-chunk $0 rows would drown the API rows the cost table exists to explain.
- **Synth model: official `Qwen/Qwen3-8B-GGUF` Q4_K_M (M12, verified 2026-08-04).** No Qwen series newer than Qwen3 exists at the 8B size on Hugging Face, and Qwen publishes an official Apache-2.0 GGUF for this one, so the unsloth-conversion fallback used for triage does not apply here. Thinking is disabled at the server with `--reasoning-budget 0` (report sections need prose, not deliberation tokens); the live gpu test asserts no `<think>` leakage.
- **Synth server measured on the RTX 5060 Mobile laptop, the deployment machine (M12, 2026-08-04; the commit body misattributes this to the desktop 4060, corrected here):** healthy spawn under the arbiter with `-fa on` and q8_0 K/V cache at 16384 context; 209-token generation in 5.92 s (35.3 tok/s, bench_vram.py). True footprint 5912 MiB, measured as the whole-card nvidia-smi delta against an idle 0 MiB baseline because per-process reporting is N/A under WDDM (the same blindness invariant 8 guards in the arbiter). Declared footprint set to 6400 MB: it fits the 6656 MB budget only alone, so the arbiter always runs synth solo, which is exactly the stage-batched design. Same-bench reference numbers on this machine: embedder 62.6 texts/s, reranker 109.5 pairs/s, one triage verdict in 1.62 s (the 95.7 texts/s M10 figure was a different power state).
- **Both GGUFs download by default (M12):** download_models.py fetches the triage and synth models regardless of engine.mode so a later engine switch never requires re-running bootstrap; `--skip-gguf` and `--skip-synth-gguf` opt out for constrained disks.
- **engine.mode lands and the default flips to local (M14):** `local | assisted | premium`, config plus a `--engine` override on `quarry research`. Premium is pinned explicitly in the API-shaped e2e tests so the new default cannot silently reroute them; `quarry verify` is engine-aware (the API key becomes a skip line in local mode, and the synth GGUF is required unless the engine is premium). The assisted mode raises a clear NotImplementedError until M16.
- **Local GAP routes through the resident triage 4B, not the 8B synth (M14):** GAP runs immediately after TRIAGE while the triage server slot is hot, so triage-routed gap checks cost zero llama-server swaps, where the synth model (resident only alone by budget math) would force a kill and respawn every loop iteration. A coverage judgment with grammar-constrained JSON output is within the 4B's demonstrated reach; revisit against live runs.
- **VERIFY stage (M15): the retrieval cross-encoder doubles as an entailment judge.** Every sentence carrying a resolving citation is scored against its cited chunk texts in one batched pass; only sentences under verify.floor pay for rewrite attempts on the triage 4B, which fits beside the reranker under the VRAM budget, so the whole stage costs at most one llama-server swap. An accepted rewrite must keep a non-empty subset of the sentence's original markers and re-score above the floor, else the sentence is dropped, so invariant 4 survives weak generators. Runs in every engine mode; rewrites stay unmetered like triage. verify.floor ships as a placeholder until the gpu-marked calibration lands (measured entry below).
- **verify.floor calibrated at -8.0 on raw logits (M15 follow-up, RTX 5060 Mobile, 2026-08-05).** The measurement exposed an implementation surprise: sentence-transformers defaults single-label cross-encoders to a sigmoid activation, so score_pairs had been returning probabilities, not the logits the M15 design assumed, and every fixture pair landed inside a 1e-5-wide band at the bottom of (0, 1) where no readable floor exists. The Reranker now pins activation_fn to identity; rerank ordering is unchanged because sigmoid is monotone, and the floor lives on the logit scale as originally intended. Measured on the relevance fixtures: grade-0 unrelated pairs score -11.04 to -8.40, grade-3 directly-answering pairs -7.12 to +0.15, and the paraphrase anchors that bound the real verify case (a chunk sentence against its own chunk vs against an unrelated chunk) sit at +10.8 vs -11.0. The floor lands at -8.0: above every observed garbage score, below every grade-3 score, biased toward keeping because a false reject costs only rewrite attempts. On the fixtures it keeps 7/7 supported and rejects 10/10 unsupported pairs; grade-1/2 related-but-not-answering pairs are a marginal band the floor is not asked to separate.
- **PDF deliverable via the `typst` pip wheel plus matplotlib Agg charts (M17):** the wheel bundles the compiler, so the PDF path is pip-only, offline (it compiles under the socket-blocked default test selection), and cross-platform; a day-one spike compiled a fixture page before the template was built. Charts derive only from run data already in hand and render only into the PDF; the markdown deliverable stays plain and is never held hostage: any PDF or chart failure logs pdf_render_failed and the run still completes. Model- and corpus-derived text is escaped for Typst markup with tested coverage; template.typ is checked in and ships inside the package.
- **Assisted tier (M16): local plan and draft, models.assisted for gap checks and one guarded polish pass.** The polish call sends the assembled draft as the prompt with the rules in the system message; the citation-marker multiset must survive exactly and the section delimiters must round-trip in order with nothing before the first one, else the polish is discarded with a warning and the local draft stands (CostCapExceeded always propagates). Polish runs inside the SYNTHESIZE checkpoint, before VERIFY, so entailment judges the final prose. Measured per-report cost lands here after the capped live smoke.
- **Assisted smoke measured at $0.0224 (M16 follow-up, 2026-08-05, run b41bf5186509).** One-iteration rehearsal, six sections, 25.2 minutes wall: the whole spend is the single Haiku 4.5 polish call (3,974 input, 3,695 output tokens); PLAN and every section draft ran on the local 8B at $0. The polish applied cleanly (marker multiset intact) and VERIFY scored the polished prose at mean logit +0.81 with 84/84 sentences kept, lower than the raw-local means (+1.4 to +2.8) because paraphrase drifts from source wording, all still far above the -8.0 floor. Caveat recorded honestly: at max_iterations=1 the loop exits at the cap without a GAP call, so the smoke measures polish only; a full-depth assisted run adds one or two Haiku gap calls of a few thousand tokens each, keeping a realistic full report well under $0.10. Gap-on-Haiku routing itself is covered by the assisted e2e test.
- **VERIFY floor validated on live runs (M15 follow-up, 2026-08-05):** sand-battery resume 1dfcc750a2e5 scored 118 cited sentences, kept 118, mean +1.415; iron-air showcase 98f5948eb366 scored 127, kept 127, mean +2.759. Real (sentence, cited evidence) pairs sit 9 to 14 logits above the -8.0 floor, and fixture garbage sits 3 below it, so the gate has wide margin on both sides in production.
- **VERIFY's rewrite-or-drop path exercised live (2026-08-05, run cea802010b68):** a deliberate QUARRY_VERIFY__FLOOR=2.0 run pushed 29 of 105 cited sentences below the floor; 9 came back as accepted rewrites (marker subset intact, re-scored above +2.0) and 20 dropped, all in about 75 seconds of rewrite passes, and the report still rendered with every surviving citation resolving. Survivor mean +4.57. The shipped -8.0 floor keeps this machinery as a safety net rather than a routine cost.
- **Assisted full-depth measured at $0.1188 (2026-08-06, run 2d30c621f031, heat-pumps topic, 3 iterations):** two Haiku gap audits ran as four calls because each 16K-token digest paid the null-missing schema retry (fixed the same night: CoverageAssessment.missing widened to str | None, saving one Haiku call per audit, about $0.02 per affected audit at these payload sizes), plus the $0.03 polish call. The polish guard fired live for the first time: Haiku's polish changed the citation-marker multiset, polish_discarded was logged, and the local draft shipped instead; VERIFY then kept 121/121 sentences at mean +2.47. Both polish branches (applied on the smoke, discarded here) are now live-proven.
- **Assisted post-fix profile confirmed at $0.0567 (2026-08-06, run b2aea99978f7, sodium-ion topic, 2 iterations):** one clean Haiku gap call (no schema retry, 12,754 in / 1,131 out) plus an applied polish (6,914 in / 6,276 out). VERIFY recorded the first organic production-floor drop: 125 polished sentences, 124 kept at mean +0.43, and one sentence whose rewrites could not clear -8.0 was removed from the report. Assisted is now measured across three executions: $0.0224 (one iteration, polish only), $0.0567 (two iterations, clean), $0.1188 (three iterations, pre-fix retry tax); the README quotes the $0.02 to $0.12 span.
- **Premium validated end to end under v1 at $2.5540 (2026-08-06, run 6bc4d96f41d3, EGS topic, 2 iterations):** plan $0.10 on Opus, gap $0.05 on Sonnet, synthesize $2.40 over one 59,950-token cache write and nine cache reads (the byte-stable prefix held; invariant 3 exercised live under v1). VERIFY judged Opus prose for the first time: 376 cited sentences, roughly three times the local engine's density, 372 kept and 4 dropped organically at the -8.0 floor, mean +0.63. The run executed against a suspension-thinned corpus (10 URLs, 4 fetched documents, 76 evidence items) and Opus flagged the corpus gaps explicitly in prose rather than papering over them. It also exposed a real defect fixed the same night: Opus opened sections with literal level-1/2 markdown headings the renderer already injects, so both synthesis paths now strip a single leading top-level heading at assembly; the premium sample PDF waits for a clean-corpus run rather than shipping with the duplicate-heading blemish.
- **The premium sample PDF is a checkpoint re-render (2026-08-06):** the validation run's original PDF predates the leading-heading fix, so the shipped sample was re-rendered from the run's persisted verify-stage draft with the fix applied, reusing the run's own charts, ledger, and manifest numbers; every cited sentence is byte-identical to the run record and the data/ originals stay untouched as that record. Cost of the re-render: zero, which is the checkpoint architecture doing its job.
- **Upstream search suspension recurred under validation load (2026-08-06):** after six search bursts in one evening, engines served zero results to 45-query bursts while single probes still succeeded, and partial recoveries re-tripped on first burst contact. Remediation that held: a strict recovery gate (three spaced probe queries, all required healthy) plus halving search.max_concurrency to 2 for subsequent runs. Two hollow runs were killed and marked failed (f1056cab524d, 51ed805136f2); checkpointed resume made the kills costless beyond one stray gap call on an empty digest.
- **Local synthesis is per-section map-reduce (M13):** body sections see only their own sub-questions' evidence (synth.section_budget_tokens, default 6000 heuristic tokens) and Overview/Conclusions see a three-claims-per-sub-question digest, while citation numbers are assigned once, up front, over the full budget-trimmed selection, so numbering stays stable across slices and the references list stays complete. Markers the index does not know are stripped deterministically before render; semantically wrong but resolving citations wait for VERIFY (M15).
